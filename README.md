# bala — ระบบติดตามยอดเหรียญลง Google Sheets

ระบบอ่านยอดคงเหลือของเหรียญในกระเป๋าที่กำหนดไว้ แล้วเขียนผลลงชีตอัตโนมัติทุกวัน
ประกอบด้วย worker 2 ตัวที่แยกกันทำงานคนละเครือข่าย

| Worker | ไฟล์ | เครือข่าย | เขียนลงแท็บ | ตารางเวลา |
|---|---|---|---|---|
| Solana | `solana.js` | Solana (SPL + Token-2022) | `Solana_Tracker` | ทุกวัน 00:00 น. ไทย |
| EVM | `evm.js` | Ethereum, BSC, Base, Linea และเชน EVM อื่นตามที่ตั้งไว้ | `EVM_Tracker` | ทุกวัน 00:00 น. ไทย |

ทั้งคู่รันบน GitHub Actions กดรันเองได้จากแท็บ **Actions** → เลือก workflow → **Run workflow**

---

## หลักการทำงานสำคัญ

### ข้อมูลเก่าจะไม่ถูกลบ ถ้าอ่านข้อมูลใหม่มาได้ไม่ครบ

ทุกรอบระบบจะ **ล้างแท็บปลายทางแล้วเขียนใหม่ทั้งหมด** ซึ่งอันตรายถ้าเครือข่ายมีปัญหา
เพราะจะกลายเป็นการลบข้อมูลดีของเมื่อวานทิ้งแล้วใส่ข้อมูลไม่ครบแทน

ระบบจึงคำนวณ **Coverage** = สัดส่วนข้อมูลที่อ่านได้จริงเทียบกับที่ตั้งใจจะอ่าน
ถ้าต่ำกว่าเกณฑ์ (ค่าเริ่มต้น **95%**) จะ **ไม่แตะชีตเลย** และทำให้ job ขึ้นแดง

> **job ขึ้นแดงเพราะ Coverage ต่ำ = ระบบทำงานถูกต้อง** ไม่ใช่ความผิดพลาด
> มันกำลังบอกว่า "รอบนี้ข้อมูลไม่ครบ ผมไม่ยอมลบของเดิมทับ" ข้อมูลในชีตยังอยู่ครบเหมือนเดิม
> ให้ไปดูสาเหตุใน log แล้วกดรันใหม่

### เครือข่ายที่เป็นเชนเดียวกันจะถูกรวมอัตโนมัติ

คอลัมน์ Network ในชีตคือ **ข้อความที่คนพิมพ์ไว้ในแท็บ `nodes`** ไม่ใช่ค่าที่อ่านมาจากบล็อกเชน
ถ้ามี 2 แถวที่ URL ชี้ไปเชนเดียวกันแต่ตั้งชื่อคนละอย่าง (เช่น `Hyperliquid` กับ `Hyperevm`)
ระบบเดิมจะอ่านเชนนั้น 2 รอบ แล้วเขียนยอดเดียวกัน 2 แถว

`evm.js` จึงถาม `chainId` จาก RPC จริงก่อนเริ่มงาน แล้วรวมรายการที่ chainId ตรงกันให้เหลือตัวเดียว
**ชื่อที่ถูกเก็บไว้คือแถวที่อยู่บนสุดในแท็บ `nodes`** — อยากให้แสดงชื่อไหนก็ย้ายแถวนั้นขึ้นไปข้างบน

## แท็บใน Google Sheet ที่ต้องมี

### `nodes` — รายการ RPC (ใช้ร่วมกันทั้ง 2 worker)

| คอลัมน์ A | คอลัมน์ B | คอลัมน์ C |
|---|---|---|
| ชื่อเครือข่าย | URL ของ RPC | ประเภท (เฉพาะ Solana) |
| `Ethereum` | `https://...` | |
| `solana` | `https://...` | `spl` หรือ `token2022` |

- แถวที่ชื่อเป็น `solana` จะถูกใช้โดย `solana.js` ส่วนที่เหลือใช้โดย `evm.js`
- เริ่มอ่านจากแถวที่ 2 (แถวแรกเป็นหัวตาราง)

### `SUBSCRIPTION WALLET` — รายการกระเป๋า

เริ่มอ่านจาก **แถวที่ 3**

| คอลัมน์ | ใช้โดย | เนื้อหา |
|---|---|---|
| A | `solana.js` | ชื่อกระเป๋า |
| B | `solana.js` | ที่อยู่กระเป๋า Solana |
| E | `evm.js` | ชื่อกระเป๋า |
| F | `evm.js` | ที่อยู่กระเป๋า EVM (`0x...`) |

### `SUBSCRIPTION SPL` — เหรียญฝั่ง Solana

เริ่มอ่านจากแถวที่ 2 · คอลัมน์ A = สัญลักษณ์ · คอลัมน์ C = mint address
ใส่ได้ทั้งค่าเดียว หรือเป็น JSON array เช่น `["mint1","mint2"]`

### `SUBSCRIPTION ERC20` — เหรียญฝั่ง EVM

เริ่มอ่านจาก **แถวที่ 3** · คอลัมน์ A = สัญลักษณ์ · คอลัมน์ C = contract address

### แท็บผลลัพธ์ (ระบบสร้างและเขียนเอง — ห้ามแก้มือ)

`Solana_Tracker` และ `EVM_Tracker` — เนื้อหาจะถูกล้างและเขียนใหม่ทุกรอบ

## การตั้งค่า

### ความลับที่ต้องใส่ใน GitHub Secrets

ไปที่ **Settings → Secrets and variables → Actions**

| ชื่อ | คืออะไร |
|---|---|
| `SPREADSHEET_ID` | รหัสไฟล์ชีต (อยู่ใน URL ระหว่าง `/d/` กับ `/edit`) |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | อีเมลของ service account |
| `GOOGLE_PRIVATE_KEY` | private key ของ service account |

> อย่าลืม **แชร์ไฟล์ชีตให้อีเมลของ service account แบบแก้ไขได้** ไม่งั้นจะเข้าไม่ได้

### ค่าปรับแต่ง (ไม่ใส่ก็ได้ ระบบมีค่าเริ่มต้นให้)

ใส่เพิ่มในส่วน `env:` ของไฟล์ `.github/workflows/*.yml` ได้เลย

**ใช้ได้ทั้ง 2 worker**

| ชื่อ | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `MIN_COVERAGE` | `0.95` | ต้องอ่านข้อมูลได้กี่ % ถึงจะยอมเขียนทับชีต |

**เฉพาะ `solana.js`**

| ชื่อ | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `RATE_LIMIT_RPS` | `3.3` | จำกัดจำนวนคำขอต่อวินาที — **ลดค่านี้ถ้ายังเจอ 429 บ่อย** |
| `NO_COLOR` | — | ใส่ `1` เพื่อปิดสีใน log |
| `FORCE_COLOR` | — | ใส่ `1` เพื่อบังคับเปิดสี |
| `RATE_BURST` | `5` | จำนวนคำขอที่ยิงรวดเดียวได้ตอนเริ่ม |
| `CONCURRENCY` | `4` | สแกนกี่กระเป๋าพร้อมกัน |
| `MAX_RETRIES` | `4` | ลองใหม่กี่ครั้งต่อ 1 คำขอ |
| `RPC_TIMEOUT_MS` | `15000` | รอคำตอบนานสุดกี่มิลลิวินาที |
| `MAX_SOCKETS` | `6` | จำนวนการเชื่อมต่อสูงสุดต่อเซิร์ฟเวอร์ |
| `EXTRA_RPCS` | — | เพิ่ม RPC เอง คั่นด้วยจุลภาค |
| `ALLOW_BLOCKED_RPCS` | — | ใส่ `1` เพื่อบังคับใช้ RPC ที่ระบบข้ามไว้ |
| `LOG_JSON` | — | ใส่ `1` ให้ log ออกมาเป็น JSON สำหรับเครื่องอ่าน |
| `LOG_SAMPLE` | `3` | แสดงเหตุการณ์ซ้ำกี่ครั้งก่อนจะย่อ |
| `FULL_SCAN` | — | ใส่ `1` เพื่อสแกนแบบละเอียด (ช้ามาก ใช้ตอนตรวจสอบ) |

**เฉพาะ `evm.js`**

| ชื่อ | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `CHAIN_ID_TIMEOUT_MS` | `10000` | รอคำตอบ chainId นานสุดกี่มิลลิวินาที |
| `MULTICALL_RETRIES` | `2` | ลองยิงซ้ำกี่ครั้งเมื่อ batch พลาด |

## วิธีอ่าน log

### สัญลักษณ์

| | ความหมาย |
|---|---|
| `✓` | สำเร็จ |
| `⚠` | ได้ข้อมูลบางส่วน — เก็บเท่าที่ได้ ส่วนที่ขาดถูกรายงานไว้ |
| `✖` | ล้มเหลว |
| `↻` | กำลังลองใหม่ |
| `⏳` | ถูกขอให้ชะลอความเร็ว (คำขอถี่เกินไป) |
| `⏸` | พักเซิร์ฟเวอร์นั้นชั่วคราว 30 วินาที |
| `⏭` | เลิกใช้เซิร์ฟเวอร์นั้นทั้งรอบ |

### รูปแบบบรรทัด

```
  ⏳ 429  api.mainnet-beta.solana.com    เราส่งคำขอถี่เกินที่เซิร์ฟเวอร์ยอมให้ · รอ 2.2 วิ แล้วลองใหม่ (ครั้งที่ 1/4)
     │    │                              │
     │    │                              └─ เกิดอะไรขึ้น และระบบกำลังทำอะไรต่อ
     │    └─ เซิร์ฟเวอร์ตัวไหน
     └─ รหัสจากเซิร์ฟเวอร์ (ค้นด้วยรหัสนี้ได้)
```

### รหัสที่เจอบ่อย

| รหัส | แปลว่า | ต้องทำอะไรไหม |
|---|---|---|
| `429` | เราส่งคำขอถี่เกินไป | ไม่ต้อง ระบบชะลอและลองใหม่เอง — ถ้าเจอเยอะมากค่อยลด `RATE_LIMIT_RPS` |
| `403` | เซิร์ฟเวอร์ปฏิเสธ มักเป็นการบล็อก IP | เปลี่ยน RPC ตัวนั้น |
| `400` + `free plan` | แพ็กเกจฟรีของผู้ให้บริการไม่รองรับเชนนี้แล้ว | เปลี่ยน RPC ตัวนั้น |
| `521`–`527` | เซิร์ฟเวอร์ปลายทางล่ม | รอ หรือเปลี่ยน RPC |
| `401` / `402` | ต้องมี API key หรือต้องเสียเงิน | เปลี่ยน RPC หรือสมัคร key |

เหตุการณ์ซ้ำ ๆ จะถูกย่อ แล้วสรุปรวมไว้ท้าย log ในหัวข้อ **เหตุการณ์ที่พบระหว่างทำงาน**

### บล็อกสรุปท้าย log

จุดที่ต้องดู 3 บรรทัด

```
Coverage: 99.1% | เขียน Sheet: ใช่          ← ผ่านเกณฑ์และเขียนแล้ว
Wallet: ครบ 92 | บางส่วน 5 | ล้มเหลว 0
Errors: 0                                   ← ถ้าไม่ใช่ 0 ให้ไปดูรายการข้างล่าง
```

- **`Warnings`** = มีบางอย่างพลาด แต่ **ข้อมูลถูกเขียนครบตามเกณฑ์แล้ว** — job ยังเขียว
- **`Errors`** = รอบนั้นไม่ได้เขียนชีต หรือเขียนไม่ครบ — job แดง
- สิ่งที่ตัดสินว่า job เขียวหรือแดงคือ **ผลลัพธ์** ไม่ใช่จำนวนข้อผิดพลาดที่เจอระหว่างทาง
- **`✓ N คำขอที่พลาดถูกลองใหม่จนสำเร็จ`** = ไม่กระทบข้อมูล ไม่ต้องกังวล

## อาการที่เจอบ่อย

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| Job แดง + `Coverage ต่ำกว่าเกณฑ์` | เครือข่ายมีปัญหา อ่านข้อมูลได้ไม่ครบ | **ข้อมูลเดิมยังอยู่ครบ** ดูใน log ว่าเซิร์ฟเวอร์ไหนพัง แล้วกดรันใหม่ |
| log เต็มไปด้วย `429` แต่ job เขียว | ปกติ ระบบลองใหม่จนสำเร็จแล้ว | ถ้ารำคาญให้ลด `RATE_LIMIT_RPS` เป็น `2.5` |
| ขึ้น `Warnings` แต่ job เขียว | มีบางเชนพลาดบางส่วน แต่ข้อมูลครบตามเกณฑ์ | ไม่ต้องทำอะไร — ถ้าเชนเดิมพลาดซ้ำทุกวัน ค่อยเปลี่ยน RPC ของเชนนั้น |
| เชนใดเชนหนึ่งขึ้น `403 Forbidden` ซ้ำ ๆ | RPC ตัวนั้นจำกัดอัตราหรือบล็อก IP ของ runner | เปลี่ยน URL ของเชนนั้นในแท็บ `nodes` เป็นผู้ให้บริการอื่น |
| ข้อมูลซ้ำในแท็บ `EVM_Tracker` | มี 2 แถวใน `nodes` ที่ชี้ไปเชนเดียวกัน | ระบบรวมให้อัตโนมัติแล้ว ดูบรรทัด `⏭ ... เป็นเชนเดียวกับ ...` ใน log |
| log ขึ้น `⊘ ... ข้ามทั้งเชน` | เชนนั้นไม่ใช่ EVM หรือไม่มี Multicall3 | ปกติ — worker อ่านเชนนั้นไม่ได้อยู่แล้ว ไม่ถูกนับใน Coverage ถ้าไม่ต้องการให้ขึ้นอีก ลบแถวนั้นออกจาก `nodes` |
| กระเป๋าหรือเหรียญบางตัวหายไป | ที่อยู่ในชีตผิดรูปแบบ | log จะเตือน `⚠ wallet address ไม่ถูกต้อง แถว N` |
| `ไม่พบแท็บ "..."` | ชื่อแท็บถูกเปลี่ยนหรือลบ | ตั้งชื่อแท็บให้ตรงกับตารางด้านบน |
| `ขาด env vars` | Secrets ยังไม่ได้ตั้ง | ตั้งค่าใน Settings → Secrets |
| `Failed to connect to Google Sheets` | ยังไม่ได้แชร์ชีตให้ service account | แชร์ชีตให้อีเมล service account แบบแก้ไขได้ |

## สำหรับนักพัฒนา

```bash
pnpm install
npm test              # 53 tests

node solana.js        # ต้องมี .env ที่มี 3 ตัวแปรความลับ
node evm.js
```

เทสต์อยู่ในโฟลเดอร์ `test/` แยกตามเรื่อง

| ไฟล์ | ครอบคลุม |
|---|---|
| `rpcpool.test.mjs` | การเลือกเซิร์ฟเวอร์ การแยกประเภท error การ retry |
| `ratelimit.test.mjs` | token bucket และการเคารพ `Retry-After` |
| `scan.test.mjs` | การเก็บผลบางส่วน และการคำนวณ Coverage |
| `logging.test.mjs` | log ต้องอ่านรู้เรื่องแต่ยังคงรหัส HTTP ไว้ |
| `blocklist.test.mjs` | การข้าม RPC ที่รู้ว่าใช้ไม่ได้ |
| `evm.test.mjs` | การรวมเชนด้วย chainId และ Coverage ฝั่ง EVM |

เทสต์ทั้งหมด **จำลองชั้นเครือข่าย** ไม่ยิงออกอินเทอร์เน็ตจริง จึงรันได้เร็ว (~15 วินาที) และไม่ขึ้นกับสภาพ RPC

## ข้อจำกัดที่รู้อยู่

- **ฝั่ง Solana เหลือ RPC สาธารณะที่ใช้ได้จริงตัวเดียว** (`api.mainnet-beta.solana.com`)
  ถ้าวันหนึ่งมันบล็อก IP ของ GitHub runner ระบบจะหยุดพร้อมข้อความชัดเจนและไม่เขียนทับชีต
  แต่ก็คือหยุดทำงาน — การเพิ่ม RPC ที่มี API key สำรองไว้สัก 1 ตัวผ่าน `EXTRA_RPCS` จะปิดความเสี่ยงนี้ได้
- **`solana.js` อ่านเฉพาะบัญชีแบบ ATA** (บัญชีมาตรฐาน) ซึ่งครอบคลุมกรณีทั่วไปทั้งหมด
  ถ้าสงสัยว่ามีเหรียญอยู่ในบัญชีแบบอื่น ให้รันด้วย `FULL_SCAN=1` เพื่อเทียบผล (ช้ากว่ามาก)
- **`evm.js` อ่านได้เฉพาะเชน EVM ที่มีสัญญา Multicall3** เท่านั้น
  เชนที่ไม่เข้าเกณฑ์ (เช่น Injective, Sui, Tron) จะถูกข้ามพร้อมขึ้น `⊘` ใน log
  และ **ไม่ถูกนับใน Coverage** — ถ้านับ Coverage จะต่ำค้างตลอดกาลจนไม่มีวันได้เขียนชีตอีก
  ยอดของเชนเหล่านั้นต้องดึงผ่าน API คนละตัว ซึ่งยังไม่ได้ทำ
- **log ของ `evm.js` ยังไม่ได้ยกระดับเท่า `solana.js`** ยังไม่มีคำอธิบายสัญลักษณ์
  การย่อเหตุการณ์ซ้ำ และตารางสรุปท้าย log
